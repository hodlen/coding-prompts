# Cleanup

Target: the supplied argument (the gate passes its baseline SHA), else the branch diff plus staged, unstaged, and untracked changes. Acceptance: applicable sections of contract ledgers (see `Agent ledgers`), synchronized with all user decisions and free of unresolved disagreements; use the request where no section applies.

Pass A uses a clean agent given the diff, the request verbatim, ledger paths and applicable sections or else the plan if any, explicit constraints, the implementation stage with its approved scope, and the `Tests as contracts` policy; Pass C a fresh agent given the final diff, changed artifacts, repository-visible references, and the `Durable artifacts` policy. Preserve accepted decisions and their reasons; independently verify prior conclusions. Review user edits, including deletions, as the current design. Agents edit and verify directly, returning conflicts or genuine ambiguity to the main agent. While a pass runs nobody else edits its files: the main agent continues independent authorized work, and the pass stops when the user edits them. Revert mutations by inverse edit, never from a snapshot.

**A. Scope and contracts.** Check the request, constraints, and authorized stage. Check ledger items applicable to the review scope: restore or report a dropped or weakened contract; record an agent edit outside authorized scope as a follow-up and remove it. Under unchanged contracts, keep inner code and explanations valid when outer implementations change. Preserve contracted intermediate stubs; flag hidden decisions, invented success, and names lacking domain meaning. Completion requires resolved stubs and satisfied required review boundaries. Keep helpers and constants local to their sole consumer unless demonstrated lifetime or identity requirements prevent it; reject manufactured references, remove names with no actual or promised use, and localize survivors. Check tests against promised behavior and supported states; remove tests lacking a rejected alternative; test mocked decisions directly and move CLI/HTTP/handler decision tests to operations. Reuse valid evidence; mutation-check uncovered risks. At the completion stage, run `mutator --changed-since <ref> --coverage-command '<project coverage command>' --test-command '<project test command>'`, choosing `<ref>` or path targets as in `/simplify`. Use explicit project commands; `--no-coverage` can replace the coverage command when every selected mutation should run. Mutation history stays in the worktree's `.metrics/mutate/`; use results applicable to the reviewed inputs and retain evidence needed for resumption or acceptance in the durable task record. Exit 2 means the baseline failed; exit 3 means a mutant survived. Judge each survivor against the contract: a promised behavior that no test rejects gets a contract test; an equivalent or unpromised mutant gets a note with its reason in the task state directory; unreachable code is deleted. Uncovered sites in changed code are findings. Skip mutation mid-work, because stubs make survivors meaningless. Inspect worktree changes after running tests and report unexpected modifications. Verify wiring and protocols through authorized live runs; report evidence or unavailable checks. Remove unrelated edits, formatting churn, unrequested features or tests, and impossible-state guards. Verify deletions by search and GitHub paragraphs for hard wraps. Fix within the authorized stage.

**B. `/simplify`** on the same target and authorized stage.

**C. Durable artifacts.** Review durable artifacts in the target scope, including earlier-session changes, under `Durable artifacts`; sessional ledgers and journals follow `Agent ledgers`. Check code-to-spec references, one-minute overviews, and domain definitions; remove code-restating comments and narrative logs, preserving diagnostic evidence. Resolve negations and decision stamps; report ambiguity. Skip mid-work only when no durable artifacts in scope need review.

Before returning, re-read the tree and review new edits; reuse findings for unchanged code.
